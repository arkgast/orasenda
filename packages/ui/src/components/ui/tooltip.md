The visible name of an `IconButton` or of the preset summary, shown on hover and on keyboard focus.

- **Anatomy:** a `surface-overlay` panel with a 1px `line-strong` edge, `radius-sm`, `body-sm` `ink` text and an optional `Kbd`. `z-popover` applies only outside the top layer.
- **Props:** `label`, `shortcut?` (one canonical glyph string, shown as a `Kbd`), `placement?: 'auto'` (below the trigger, flipped above when it does not fit; never covering the trigger), and `children`: exactly one focusable trigger.
- **Using it:** `IconButton` renders its own Tooltip; don't wrap one in another. Anything else (the preset summary) wraps its one focusable trigger: `<Tooltip label="Change preset" shortcut="P"><button …>Classic · ends 15:20</button></Tooltip>`. The trigger's accessible name holds `label` (an `IconButton`'s is exactly `label`; the preset summary's is its visible text, then "Change preset"), and the host sets the trigger's `aria-keyshortcuts` to `describeShortcut(shortcut).aria`. The Radix Trigger adds `data-state` and, while the tooltip shows, `aria-describedby` to that child; the Tooltip adds only its pointer and focus handlers, after the child's own.
- **Placement:** Radix Popper, `side="bottom"` with a `space-1` gap, flipped above when it does not fit, centred on the trigger and kept `space-2` inside the viewport; it follows resize and scroll. It is never a `popover` and never uses CSS anchor positioning, which the macOS 13 WebKit lacks. The panel is portalled into `layerContainer(trigger)` (`src/lib/layer.ts`): the open Radix `Dialog` content if any, else the nearest open native `<dialog>` (a `showModal()` dialog is in the top layer, which no z-index reaches, so the panel joins it), else the page body. It is removed when it hides.
- **Single keys:** a `Kbd` for a single key (Space, F, P) shows only while the Single-key shortcuts setting is on. When it is off the host drops that `shortcut`, so the tooltip drops that `Kbd` and the trigger drops that key from `aria-keyshortcuts`, keeping any ⌘ combination. The preset summary's tooltip reads "Change preset", with the P `Kbd` only while the setting is on. Tips and captions follow the same rule.
- **Behaviour:** opens after `duration-quick` on hover. Opens on focus only after the window has seen a keyboard navigation event (Tab, an arrow, Home, End, Page Up or Page Down): an input-modality flag, because WebKit matches `:focus-visible` for programmatic focus too. Any pointer press or any other key clears the flag, so launch focus on Start, or focus restored after a dialog closes, opens nothing. Stays while the pointer is over the trigger or the panel (WCAG 1.4.13): leaving waits `duration-quick` before hiding. At most 40ch wide and two lines, never ellipsized; the `Kbd` never breaks. No motion, so nothing changes under reduced motion.
- **Keyboard:** Esc hides it without moving focus, and does nothing else on that press (no dialog closes). That press is spent on the tooltip: host Esc handlers (Leave full screen, `CommandPalette`) get the next press, so a keyboard user on a tooltip trigger presses Esc twice. Two exceptions: an Esc pressed with focus inside an open `PopoverMenu`, and one pressed inside an element marked `data-os-esc` (`FullScreenFocus`, where Esc means Leave full screen): the tooltip still hides, but the press is not stopped, so the menu closes, or the leave dialog opens, on that same press. Host Esc handlers must be element or React handlers, not `window` or earlier `document` capture listeners, which this one cannot stop. While a tooltip shows, Radix calls `preventDefault()` on that Esc keydown, including the in-menu press that is not stopped, so `defaultPrevented` is true there even though propagation continues. It shows again on the next hover or focus.
- **Menu triggers:** the tooltip never shows while its child has `aria-expanded="true"` (a menu trigger whose `PopoverMenu` is open; the host sets it). So with the menu open, Esc closes the menu, not a tooltip; a tooltip showing on some other trigger (under a resting pointer) hides on that same press without taking it from the menu, and focus returned to the trigger after Esc or a choice opens no tooltip (Esc and Return are not navigation keys). It reads the child's `aria-expanded` prop, so the host passes it on that child (`IconButton` passes it to its button).
- **VoiceOver:** the panel is `aria-hidden`, and its `Kbd` glyph too. Radix points the trigger's `aria-describedby` at that panel while it shows, so a description that repeats the label and the shortcut may be read after the trigger's name; this is to be checked on a device (#61). It adds no live region. If device testing shows WKWebView does not speak `aria-keyshortcuts`, give the tooltip's `Kbd` the same hidden spoken name as a tip's `Kbd`.

Do: keep the text equal to the accessible name, or to the part of it that the visible text does not say. Don't: put actions or links in a tooltip, or use the native `title` attribute.
