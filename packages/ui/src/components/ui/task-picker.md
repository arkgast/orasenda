The optional task for a session, on Today and the timer surfaces. It stays quiet until the person wants it.

- **Anatomy:** at rest, plain `ink-muted` text, `body-sm`, "Add a task" (`quietLabel`): a native button with no border and no fill, `hit-min` high through its padding, a 2px `focus-ring` at the fixed 2px offset, and `ink` on hover. Activating it swaps the text for an `Input` (its label "Add a task" is visually hidden; the placeholder says "Find a task"). The options panel is not there yet: it appears under the input once the person types, or after ↑/↓. It is: `surface-overlay`, 1px `line-strong` edge, `radius-md`, `shadow-overlay`, `z-popover`, as wide as the input, scrolling inside when long. With a task chosen, the rest state is the title as the same quiet text (one line, ellipsis) and an `IconButton` "Clear task" (`close`) beside it.
- **Props:** `task?: { id, title }`, `options: { id, title, order, laneLabel, frog?, week? }[]`, `onPick(id | null)`, `quietLabel?` and `onCreate?(title)`. The host passes the task-able options (not done) the column word in `laneLabel` (a default or custom column name) and a sort key in `order` (a number, lower first); it owns where the task goes.
- **Optional by design:** nothing here is required. Esc, a click or Tab away, or an empty panel all leave things as they were and call nothing.
- **Options:** shown once the query is not empty, or after ↑/↓ asks for the list (not on open), and they stay for the rest of that open. The panel sits under the input; when the room below is under two rows (2 × `hit-min`) and there is more room above, it opens above the input instead (`data-placement`). Either way it is capped at the room on that side less `space-2` (read from the token), measured when it shows and on resize, and scrolls inside. Inside a `ScrollRegion` the room is measured against the region (which clips the panel), not the window. A short title keeps a target at least `hit-min` wide. The filter is a case-insensitive substring of the title. They are ordered by `order`, lowest first, and keep the host's order between options with the same `order`. Each row shows the title (one line, ellipsis) and, at the end, the column in words ("Doing") plus " · Frog" for the Frog and " · This week" for a task planned for the week (after the Frog, in the row text and its name), so neither rests on colour or position. The active row is on `selection` and also has a `focus` bar at its start and the word "Selected", so it never rests on colour alone; arrowing scrolls it into view inside the panel; hover is `surface-sunken`. Rows are at least `hit-min` high. With nothing to show the panel says "No matching tasks" (not a live region).
- **Add row (`onCreate`):** with `onCreate` and a query that is not empty once trimmed, the last row reads `Add "<query>" to Backlog`: the same `hit-min` height, the same active-row `focus` bar and "Selected" word, `role="option"`. A long query truncates with an ellipsis; the name stays the full sentence. Arrows reach it (wrapping), Return or a click calls `onCreate(trimmed query)` and closes with focus on the quiet text. It is never applied on its own: Esc, blur and an empty query call nothing, and with no match the panel shows only this row. Without `onCreate` nothing changes.
- **Keyboard:** Return or Space on the quiet text opens the input with focus in it. ↑/↓ show the panel if it is hidden (the first option active), then move the active option (wrapping); Return with the panel hidden does nothing, Return picks it and closes (focus goes back to the quiet text), Esc closes without picking and returns focus to the quiet text, and Tab or any blur closes without picking (focus stays where the person sent it). The Esc is stopped here, so a page or window that closes on Esc does not also close.
- **Clear:** after "Clear task" removes the task, focus goes to the quiet text, so it never falls to the page.
- **Pointer:** pressing an option keeps focus in the input and picks it on click. "Clear task" calls `onPick(null)`. Activating the title reopens the input with a fresh filter.
- **VoiceOver:** the input is `role="combobox"` with `aria-expanded` (true only while the panel lists options), `aria-autocomplete="list"`, `aria-controls` (the listbox, while it has options) and `aria-activedescendant` (the active option). The panel's list is `role="listbox"` named "Tasks"; each row is a `role="option"` with `aria-selected`; its text reads "Draft the outline Doing · Frog". At rest, the title button is named "Task: <title>. Change task". No live region: the host announces the result of a pick where it already does.
- **Motion:** none beyond the colour change on hover, which is instant under reduced motion.
- **Contrast:** `ink-muted` on `surface` is at least 4.5:1 in both themes; the panel's edge is `line-strong` (3:1).

Do: keep it as quiet as a caption until the person reaches for it. Don't: make it required, pick or create anything on blur or Esc, give it a border at rest, or colour a column to tell it apart.
