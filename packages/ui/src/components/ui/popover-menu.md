The one in-webview menu, for a choice that needs radios and a heading: the preset on Today and in the Focus window, and an app's role on Apps and sites.

- **Anatomy:** a `popover-width` panel on `surface-overlay`, 1px `line-strong` edge, `radius-md`, `shadow-overlay`, `z-popover`; a heading row (`body-sm` `ink`, weight 600, with the P `Kbd` at its end when `singleKeys` is true), an optional second line (`body-sm` `ink-muted`), rows of at least `hit-min` (44px), a separator (a full-width 1px `line` rule with a `space-2` gap above and below) and an optional link row.
- **Props:** `heading`, `description?`, `items: { id, label, meta?, kind: 'radio' | 'checkbox' | 'link', checked?, disabled? }`, `readOnly?`, `onSelect(id)`, `onClose()`, `id?`, `anchor` (a ref to the trigger) and `singleKeys?`. The host renders the menu only while it is open and owns that state; choosing calls `onSelect(id)` and then `onClose()`.
- **The trigger is the host's:** an `IconButton` with `aria-haspopup="menu"`, or the preset summary's own button. The host sets the trigger's `aria-expanded` from its open state and `aria-controls` to the menu's `id`; `id` is settable for that (otherwise generated) and lands on the `role="menu"` element. `PopoverMenu` reads `anchor` only to place itself and to return focus; it never writes the trigger's attributes. `anchor` is the trigger or an element that holds it: `IconButton` takes no ref, so wrap it in a span that carries the ref (`<span ref={anchor}><IconButton … /></span>`); focus then returns to the first focusable element inside.
- **Placement:** a Radix `DropdownMenu` (controlled open, non-modal), placed by Radix Popper against `anchor`, never a `popover` and never CSS anchor positioning (the macOS 13 WebKit has neither). On open the panel portals into the topmost open layer (an open `Dialog`'s content, else the nearest open native `<dialog>`, else the page body: `layerContainer` in `lib/layer`), so the menu shows above a dialog. It is start-aligned with the trigger, below it with a `space-1` gap, flipped above when it does not fit, and kept `space-2` inside the viewport; the panel caps its height at Radix's available height (`var(--radix-dropdown-menu-content-available-height)`), so on a window as short as 240 it stays inside and scrolls inside when taller. It is placed again on every resize and scroll. It is `popover-width` wide and fits a 360-wide window. The panel carries `data-side` (`bottom` or `top`).
- **States:** a checked radio shows the `Choice` radio shape (a circle with a filled `focus` dot) on `selection`; a checkbox row shows the checkbox shape (a tick on `focus`) plus an Off/On word; hover `surface-sunken`; disabled rows have a dashed ring and `ink-muted` text. Keyboard focus is the 2px `focus-ring` at the fixed 2px offset; rows sit `space-1` inside the panel so the ring stays inside it. No motion, so nothing changes under reduced motion.
- **Read-only (a session is running):** `readOnly` keeps every radio and checkbox row's checked state and gives it `aria-disabled` (focusable, never chosen); link rows stay live. The host passes the heading "Classic · 25 / 5" and the line "Presets can change between sessions.", so the current radio is checked, the others wait, and the Settings row still opens Settings.
- **Focus window:** opens only while idle. The host passes items without the Settings link row, the heading "Preset for the next session" and the line "Choosing one applies it and closes."
- **Keyboard:** the host opens it with click, Return or Space on the trigger, or P on Today while single-key shortcuts are on (the P key is the host's; the menu never listens for it). Focus moves to the checked radio, or the first row. ↑/↓ move (wrapping; Home and End go to the ends), Return or Space chooses and closes (on a checkbox row choosing toggles it), Esc closes, and Shift+Tab closes (a letter key moves focus to the row that starts with it, as in Radix, and Space is ignored for about a second after a letter); each returns focus to the trigger. Tab closes and moves focus to the next tabbable element after the trigger (inside the open dialog that holds the trigger, if any), as in the WAI-ARIA menu pattern; with none after it, focus returns to the trigger. A press outside the menu and its trigger closes it and leaves focus where the press put it. The menu's keys stop there, so a page key such as Space for Pause never sees them, and Esc inside an open dialog closes only the menu.
- **Pointer:** hovering a row moves keyboard focus to it (Radix), so the roving row follows the pointer.
- **Tooltip:** the trigger's tooltip never shows while the trigger has `aria-expanded="true"`, so Esc in an open menu closes the menu and the tooltip has nothing to hide. A tooltip still showing on some other trigger (the pointer resting on it) hides on that same Esc press and the menu still closes: one press, focus back on the menu's trigger (Tooltip README).
- **Single keys:** `singleKeys` true shows P as a `Kbd` at the end of the heading row (its glyph `aria-hidden`), and the host adds `P` to the trigger's `aria-keyshortcuts` (with `describeShortcut('P').aria`). Omitted or false, neither appears. Pass it only while the Single-key shortcuts setting is on.
- **VoiceOver:** `role="menu"` labelled by the heading (`<id>-heading`) and described by the second line (`<id>-desc`); rows are `menuitemradio`, `menuitemcheckbox` (with `aria-checked`) or `menuitem`. The dot and the tick are the non-colour cues; there is no "Current" word. No live region.

Do: use it only for a choice. Don't: use it for navigation or commands (those are native NSMenus), stack two, or set the trigger's attributes from inside the menu.
