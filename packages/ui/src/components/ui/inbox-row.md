One captured note in the Inbox list.

- **Anatomy:** a list item (`li`; focusable when the host gives it a `tabIndex`) with the note text in `ink` (`body`), then a meta line in `ink-muted` (`body-sm`): the kind as a word, "Internal" or "External", a "·" and the time. A 44 × 44 (`hit-min`) `IconButton` with the `close` icon sits at the end. A `line` rule closes the row.
- **Props:** `text`, `kind` (`"internal" | "external"`), `time` (as shown, "09:41"), `timeLabel` (the time in words for VoiceOver, "Captured at 9:41 AM"), `onRemove()`, `removeName` (the Remove button's name), and optionally `onMoveToBoard()`, `moreName` ("More actions for Ask Sam about the invoice"), `tabIndex` (`0 | -1`), `menuTabIndex` (`0 | -1`, default `0`) and `onKeyDown`.
- **Row menu:** with `onMoveToBoard`, the end of the row is a `menu` `IconButton` named `moreName` (`aria-haspopup="menu"`, `aria-expanded`, and `aria-controls` the open menu) in place of the Remove button, and a `PopoverMenu` headed "This note" offers "Move to Board" and "Remove" (Remove calls `onRemove`, Move to Board calls `onMoveToBoard`; the menu closes, and Esc returns focus to the button). The More button shows `⇧F10` in its tooltip and sets `aria-keyshortcuts="Shift+F10"`. Without `onMoveToBoard` the row is exactly as before: the `close` Remove button named `removeName`, so the host that cannot move notes yet loses nothing.
- **Roving focus:** the host owns it. `tabIndex` 0 puts the row in the tab order, -1 keeps it reachable by script only, and omitted leaves the row out. `onKeyDown` receives keys pressed on the row or inside it (the host handles ↑/↓, and ignores keys whose target is the menu button or an open menu). A focused row shows the 2px `focus-ring`, one ring, drawn inside the row (the base outline with a -2px offset, set in `styles.css`) so the list never clips it.
- **One tab stop, and the menu key:** a row that roves passes `menuTabIndex={-1}`, which takes the More button out of the tab order, so Tab from the row leaves the list. It still opens by click. On the focused row itself (not on a key typed in its menu button or open menu), `ContextMenu` or `Shift+F10` opens the menu with focus on the first item; the row calls `preventDefault` on the key and runs this before `onKeyDown`. It also calls `preventDefault` on the native `contextmenu` that follows a keyboard Shift+F10 (WebView2). With the menu already open the key does nothing more. A menu opened by key returns focus to the row on Esc and on choosing; a menu opened by click returns it to the More button. The prop does not apply to the Remove button of a row with no menu. A row that does not rove (a lone specimen) keeps the default `0`.
- **Text:** it wraps at spaces and breaks a long word, and keeps its line breaks. It is never truncated or clamped, so a 1000-character note shows in full and the row grows.
- **States:** rest; the Remove button has the `IconButton` hover, pressed and focus states (2px `focus-ring`, 2px offset). The row itself (when focusable) shows the 2px `focus-ring` outline drawn inside it (offset -2px, no second ring), so a scrolling list never clips it. `moreName` is required with `onMoveToBoard` (typed as a union). The kind is always a word, never colour alone.
- **VoiceOver:** the visible time is `aria-hidden` and `timeLabel` is read instead. The Remove button's name is `removeName` exactly ("Remove note: Ask Sam about the invoice"); the tooltip is `IconButton`'s own. No live region.
- **Host provides:** the roving `tabIndex` and arrow keys, the "Moved to Board" status, the surrounding `ul` and the row's width (the row has no cap of its own; it keeps `space-1` free at the end so the Remove focus ring is not clipped), the first-40-characters `removeName`, the formatted `time` and `timeLabel`, and the "Note removed." status line with Undo after `onRemove`.
