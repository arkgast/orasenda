# Board columns — Implementation Plan

- Spec: [docs/specs/2026-11-18-board-columns.md](../specs/2026-11-18-board-columns.md)
- Date: 2026-11-18
- Status: draft

## Overview
Eight tasks, each one PR. Tests come first in every task. Every file stays at 500 lines or fewer, and every task passes `./scripts/ci.sh`. UI tasks get the opus design review. The owner reviews visuals, so PRs carry no screenshots.

The lane type changes in the store and the service at once: the workspace has to compile, so **B1** turns `Lane` into a string from the store through the bindings, with behaviour unchanged (still four columns). **B2** builds the column rules on top of it. The two design-system tasks (**B3** `ScrollRegion`, **B4** `KanbanColumn` and `ColumnEditor`) need nothing from the backend and start at once. The Board page is two tasks in a row: **B6** (scroll, saved folds, custom lanes in keys and drag), then **B7** (the header's +, the editor, add and remove, arrows into the header). **B5** (TaskPicker order) runs beside them. **B8** closes out.

## Contract
- **B1** owns:
  - `crates/store` `tasks::Lane`: `pub struct Lane(String)` with `Lane::BACKLOG`, `TODAY`, `DOING`, `DONE` (`fn backlog() -> Lane` etc. if consts can't hold a `String`), `Lane::parse(&str) -> Option<Lane>` (a built-in or `c_` + 8 of `[0-9a-z]`), `as_str(&self) -> &str`, `is_builtin(&self) -> bool`. `TaskRow.lane: Lane`, `NewTask.lane: Lane`, `move_to(.., lane: &Lane, ..)`.
  - `tasks::count_live_in(txn, lane: &Lane) -> Result<u32, StoreError>`; `tasks::lanes_live(txn) -> Result<Vec<Lane>, StoreError>` (distinct lanes of live tasks).
  - `crates/service` `api::Lane`: `#[serde(transparent)]` string newtype (TS `Lane = string`), same constructors as the store's, plus `Builtin` (`Backlog | Today | Doing | Done`) and `Lane::builtin(&self) -> Option<Builtin>`.
  - `SCHEMA_VERSION` 11.
- **B2** owns:
  - `ColumnSettings { lane: Lane, name: String, limit: Option<u8>, order: u8, folded: bool }`; `ColumnView` gains `custom: bool`, `folded: bool`.
  - Commands (Tauri and TS `commands.*`): `board_column_edit(lane: Lane, name: String, limit: Option<u8>) -> Result<(), BoardError>`; `board_column_add(after: Lane) -> Result<Lane, BoardError>`; `board_column_remove(lane: Lane) -> Result<(), BoardError>`; `board_column_fold(lane: Lane, folded: bool) -> Result<(), BoardError>`. `board_columns_set` removed.
  - `BoardError` gains `TooManyColumns`, `ColumnNotEmpty`, `ColumnNotFound`, `BadColumnName`, `BadLimit` (with their words in the error mapping: "Up to 4 extra columns.", "Move its tasks out first.", "That column is gone. Pick another.", "Another column has that name." / "A name needs 1 to 24 characters.", "That limit isn't allowed here.").
  - `useBoard()` returns `editColumn(lane, name, limit)`, `addColumn(after) -> Promise<Lane | null>`, `removeColumn(lane)`, `foldColumn(lane, folded)`; `setColumns` removed.
- **B3** owns: `ScrollRegionProps.axis?: "y" | "x"` (default `"y"`).
- **B4** owns:
  - `KanbanColumnProps` gains `onAdd?: () => void`, `onEdit?: () => void`, `editor?: ReactNode`, `addLabel?: string` (defaults to "Add task to <title>"). The `action` prop is removed if nothing uses it (grep first; keep it otherwise).
  - Data slots: `kanban-column-name`, `kanban-column-add`, `kanban-column-fold` on the three header controls.
  - `ColumnEditor` (`packages/ui/src/components/ui/column-editor.tsx`), exported from `@orasenda/ui`, with `ColumnEditorProps` as in the spec (Column editor): `name`, `limit: { value: number; min: number; max: number; zeroLabel?: string } | null`, `error?: string`, `taken: readonly string[]` (other columns' names, for the uniqueness check), `canAdd: true | { reason: string }`, `canRemove: true | { reason: string } | null`, `onSave(v: { name: string; limit: number | null }): void`, `onCancel(): void`, `onAdd(): void`, `onRemove(): void`.
- **B5** owns: `TaskPickerOption.order: number` replaces the fixed `lane` union for sorting; `hint` stays the column's name.

  - TS: `features/board/*` (`lanes.ts`, `useFolds.ts`, `dragGeometry.ts`, `dragMeasure.ts`, `useCardDrag.ts`, `useBoardKeys.ts`, `useBoardActions.ts`, `BoardColumns.tsx`, `BoardCard.tsx`, `BoardPage.tsx`, `detail/TaskSheet.tsx`), `shared/test/fixtures/board.ts`, `domain/board/useTaskOptions.ts`, `app/palette/paletteCommands.ts`, `packages/ui` `task-picker.tsx`.
- **Data and migrations:** one expand step. 0011 rebuilds `task` with a wider CHECK; old values stay valid, so no data changes. The `board.columns` row reads both shapes (spec, Domain model) and is rewritten in the new shape only on the next column write.
- **Tests and downstream checks that must stay green:** store migration and portability tests; every service board, review, session and import test; the Board, Today, palette and Inbox vitest suites; `just bindings` with no diff after regeneration; `just contrast`.
- **Rollout and rollback:** local app. A v11 database can't be opened by an older build (the schema-version check refuses it); dev data is disposable. Rolling back a merged task is a revert PR; reverting B1 after B2 has landed means reverting B2 first.
