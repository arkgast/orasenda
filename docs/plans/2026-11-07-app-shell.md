# App shell — Implementation Plan

- Spec: [docs/specs/2026-11-07-app-shell.md](../specs/2026-11-07-app-shell.md)
- Date: 2026-11-07
- Status: draft

## Overview
Five tasks. T1 lays the foundation every other task builds on: the Cargo and pnpm workspaces,
the pinned toolchains, Biome, the `justfile` with its `ci` recipe, the macOS `ci` and Windows
advisory CI jobs, and `crates/core` (the pure domain types). After it, the design tokens (T2) and
the Tauri app crate with its IPC contract (T3) run in parallel. The UI (T4) needs both. The mobile
projects and README (T5) need only T3 and run alongside T4.

`crates/core` sits in T1 rather than its own task because a Cargo virtual workspace with no
members cannot run `cargo fmt`, `clippy` or `test`, and core is small (three files).

There is no lockfile yet, so the vet step of `baton:deps` (add in a copy, audit) cannot run at plan

on its own day; a newer non-pre-release version then replaces the one above.

## Contract
- **IPC contract (T3):** command `app_info() -> AppInfo`, event `clock-tick` with
  `ClockTick { epochMs: number }`, exported to the committed `apps/orasenda/src/bindings.ts`.
  T4 builds against `bindings.ts` and mocks IPC with `mockIPC`.
- **Token contract (T2):** `packages/tokens/tokens.css`, CSS custom properties named
  `--<token-name>` (e.g. `--surface`, `--ink-muted`, `--space-2`), `--font-sans|mono|alt`, and
  `--type-<style>-<property>` for type styles. T4 consumes it.

## Impact
Shared modules: the whole build and CI path changes.
- **Affected call paths / consumers:** `scripts/ci.sh` becomes `exec just ci`; `baton verify` and
  GitHub Actions both run it. The `ci` job moves from `ubuntu-latest` to `macos-26`.
- **Data and migrations:** none.
- **Tests and downstream checks that must stay green:** branch protection requires context `ci`
  (strict). T1 keeps the job id and name `ci` with no matrix, or every later PR is unmergeable.
  The gitleaks step and `CI_BASE_REF` logic stay as they are.
- **Rollout and rollback:** each task is one squash-merged PR; revert that PR to roll back. If
  `macos-26` runners are unavailable, T1 falls back to `macos-15` and says so in its PR.

## Dependency graph
```
T1 ──> T2 ──> T4
T1 ──> T3 ──> T4
       T3 ──> T5
```
Can start immediately: T1. After T1: T2 and T3 in parallel. After T3: T5 (and T4 once T2 is in).

Additive touches: T2 and T3 can run at the same time and both add lines to `justfile` (their own
recipes and their steps in `ci`) and to root config. Each adds its own lines only; the second to
merge rebases.
