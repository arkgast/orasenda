- Spec: [docs/specs/2026-11-08-focus-session-loop.md](../specs/2026-11-08-focus-session-loop.md) (as merged in #83, amended by this plan's PR; see "Spec and ADR-012 amendments")
- Date: 2026-11-08
- Status: done (T1–T10 merged: #95–#110; owner's manual acceptance recorded in #110)

## Overview
Ten tasks in five waves. The spec estimated eight; two were added so that frontend and backend
never wait on each other and so that no two parallel tasks own one file:

- **Wave 1** lays the two contracts nothing else can start without: the core types, traits
  and the hybrid logical clock (T1) and the design-system README note (T6, design-first, done
  by the orchestrator).
- **Wave 2** runs three tasks in parallel on T1: the IPC contract with stub commands and the
  regenerated `bindings.ts` (T2), the timer engine with formatting (T3) and the new
  `crates/store` (T4). The macOS platform implementations (T5) start as soon as T4 merges, and
  T7 waits for T5: T4, T5 and T7 each add to the root `Cargo.toml` and `Cargo.lock`, so they are
  chained rather than parallel. T5 is small and T7 waits on T2 and T3 anyway, so this costs
  little or no time.
- **Wave 3** builds the session service, the scheduler and the real command bodies in the app
  crate (T7, on T2, T3 and T5, against the traits with fakes) while Today and the shell UI (T8)
  build against `bindings.ts` and `mockIPC` (on T2).
- **Wave 4** wires macOS: the menu-bar item, hide-on-close, Dock reopen, the platform
  selection and the exit flush (T9, on T6 and T7).
- **Wave 5** flips the ADR statuses, updates the conventions and the spec status, and carries
  the owner's manual acceptance checklist (T10).

Core is cut in two (T1 types, traits and `Hlc`; T3 engine and formatting) so the IPC contract
(T2) and the store (T4) can start after a small, quick task instead of after the whole engine.
The app crate is cut in two (T7 cross-platform service, T9 macOS glue) along the same line as
the spike (S5a/S5b): T7 is testable on every OS with fakes, T9 is the AppKit and tray work.

**Conventions for every task** (from `docs/conventions.md`, `docs/common-issues.md` and the
earlier plans): IPC structs and enums use `#[serde(rename_all = "camelCase")]`, enum variants
are lowercase or camelCase as the spec spells them; every `u64` that crosses IPC carries
`#[specta(type = specta_typescript::Number)]` (an `Option<u64>` carries
`#[specta(type = Option<specta_typescript::Number>)]`), because specta-typescript 0.0.13 exports
`f64` as `number | null`; `bindings.ts` is generated by `cargo test -p orasenda export_bindings`
and never edited by hand; every command goes into `commands.list.rs` **and** a capability file,
and its generated `permissions/autogenerated/<command>.toml` is committed; no lock is held
across an AppKit, tray, menu or window call; `unsafe` blocks carry a `// SAFETY:` comment;
green CI means `gh pr checks <pr> --required` passes; the `windows (advisory)` job is **already
red on `main` at the mobile step** (`objc2-exception-helper` needs `xcrun` for
`aarch64-apple-ios`, run 42543626162, issue #78), so "Windows no worse" means "on Windows the
clippy and `cargo test` steps pass; the mobile step's red is the known baseline (#78)", and no
task here fixes #78; `Cargo.lock` and `pnpm-lock.yaml` are regenerated after a rebase, never
hand-merged. Each task is one squash-merged PR. Tasks marked **mechanical** have a fixed shape
and a complete contract to type against; tasks marked **cross-file/debugging** need judgement
across modules or the running app.

## Spec and ADR-012 amendments
Planning found five places where the approved contract could not be built as written. The
resolutions change the contract, and the conventions require decisions before the code, so
this plan's PR amends the spec and ADR-012 (the diff is in the same branch) rather than only
listing gaps. T10 then only flips the ADR statuses.

1. **`SessionId(String)` instead of `id: Uuid` in core.** The spec's dependency table puts
   `uuid` in the app crate only. Core carries the UUIDv7 as `SessionId(String)`
   (`#[serde(transparent)]`); the app crate makes it with `Uuid::now_v7().to_string()`.
2. **The device id is passed into the store.** The store never makes ids or reads the clock,
   so `Store::open(path, new_device_id)` and `Store::open_in_memory(new_device_id)` take a
   UUIDv4 the app crate makes (`uuid` feature `v4`); the store writes it to `meta` only when
   absent.
3. **`store.write(now_ms, |txn| …)`.** The hybrid logical clock needs the current time for
   every stamp and repositories need it for `updated_at` (`txn.now_ms()`). ADR-012's
   `write(|txn| …)` becomes `write(now_ms, |txn| …)`. Repositories write their own row and
   call `txn.log_fields(entity, id, fields)` for the change log (ADR-012's `set_fields` could
   not fill `created_at` and `updated_at` generically).
4. **One `timer-tick` on every notification-status change, in every state.** The spec said the
   explanation line disappears "as soon as" the status changes but also that nothing is
   emitted on `timer-tick` while idle. Each change of the status (the launch read, a request
   answer, the re-read at a completed end) now emits exactly one tick, idle included; an
   unchanged read emits none.
5. **`HlcStamp` counter width is five digits** (`{counter:05}`): a `u16` reaches 65535, and
   `{counter:04}` would break string order from 10000 up.

Also renamed: `windows.rs` → `lifecycle.rs` (the spec's Interfaces list), because `windows`
is the name of a crate the boundary check watches for.

## Impact
Risky changes: a new database and schema, a larger IPC public surface, the shell ticker
replaced, the window lifecycle changed, the CI script extended.
- **Schema (T4):** new file `orasenda.db` under `app_data_dir()` (created with
  `create_dir_all` first: SQLite does not create parent directories); `0001_init.sql` creates
  `meta`, `change_log`, `setting`, `focus_session`, `active_session`; `PRAGMA user_version = 1`.
  No existing data, so expand → migrate → contract collapses to "create". A newer
  `user_version` is refused and the app runs degraded (`store: newer`); nothing is written.
  Rollback of the feature leaves the file in place and unread, which is harmless.
- **IPC public surface (T2):** `ClockTick` gains `clock: string` and `idleFinish: string | null`
  (additive; the shell's `useClock` keeps working until T8 replaces it); seven new commands,
  two new events. `bindings.ts` is regenerated in T2 and must not change in T7 (T8 runs in
  parallel against it); the `windows (advisory)` job regenerates it too, so every new type must
  exist on every OS (none is `cfg(target_os)`-gated).
- **Ticker replacement (T7):** `ticker.rs` is deleted and `scheduler.rs` takes over
  `clock-tick`; `lib.rs` calls `scheduler::spawn` and `scheduler::publish_focus` where it
  called `ticker::spawn` and `ticker::emit_now`. The shell's `clock-tick` contract stays (one
  tick a second, one on `Focused(true)`), so `App.test.tsx`'s clock tests keep passing until T8.
- **Close-to-hide (T9):** `CloseRequested` on `main` is prevented and hides; the process stays
  alive with the menu-bar item; ⌘Q and *Quit Orasenda* quit. Rollback: revert T9 and the app
  quits on close again, with no data effect (the live session is persisted on every
  transition).
- **Threading (T7, T9):** Tauri 2 runs non-async commands and menu events on the main thread,
  and `TrayIcon::set_title`/`set_icon`/`set_menu` called from another thread go through
  `run_on_main_thread` and wait for it. So the scheduler thread must never hold a mutex the
  main thread may want while it calls a tray API, and the main thread must never wait on a
  thread that may itself be waiting on the main thread. The plan's rule: the timer commands and
  `settings_set` are `async fn` whose whole body is
  `tauri::async_runtime::spawn_blocking(move || run_action(&app, …)).await` (the work is
  blocking: a `std::sync::Mutex`, SQLite writes, and `publish`, which may read the notifier
  status for up to 3 s); `settings_get`, `publish_focus` and the `Exit` flush take the service
  lock briefly on the main thread, which is safe because nothing inside that lock waits on
  another thread; menu events hand the action to `tauri::async_runtime::spawn_blocking`,
  `Surfaces` is a `Vec<Arc<dyn NativeSurface>>` cloned under its lock and rendered after unlock,
  and `Tray` computes under its own lock and calls AppKit after unlock. T7 and T9 carry this as
  acceptance.
- **CI script (T1, T4):** `just core-boundary` also rejects `rusqlite` and `libsqlite3-sys`; a
  new `just core-purity` step fails when a non-comment line in `crates/core/src` mentions
  `target_os` (so `cfg(any(target_os…))`, `cfg(not(target_os…))` and `cfg!(target_os…)` all
  fail); the mobile step becomes `cargo check -p orasenda-core -p orasenda-store -p orasenda`
  for both targets and **needs an Android NDK clang** for the `bundled` SQLite C build (see
  Dependencies): the recipe exports `CC_aarch64_linux_android` and `AR_aarch64_linux_android`
  from the first NDK it finds (`ANDROID_NDK_HOME`, `NDK_HOME`, `ANDROID_NDK_LATEST_HOME`, the
  newest `$ANDROID_HOME/ndk/*`, then `~/Library/Android/sdk/ndk/*`) and fails with a message
  naming the variables when none exists. No workflow change. On the Windows job the mobile
  step stays red as on `main` (#78).
- **Tests and downstream checks that must stay green:** the core boundary step, core mobile
  check, `bindings.ts` staleness on macOS and Windows, the spike's Vitest suites
  (`DevPanel.test.tsx`, `useSpike.test.tsx`, `overlay.test.tsx`, `spike/styles.test.ts`),
  `manifest_commands_match_specta_builder`, `main_capability_includes_spike_commands`,
  `styles.test.ts` (the token-only CSS rule now also covers Today's CSS).
- **Rollout and rollback:** each task is one squash-merged PR; revert that PR to roll back.
  T6's design-system change is rolled back by republishing the previous artifact version and
  refreshing `design/system/`.
