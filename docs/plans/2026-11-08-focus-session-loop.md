# Focus session loop — Implementation Plan

- Spec: [docs/specs/2026-11-08-focus-session-loop.md](../specs/2026-11-08-focus-session-loop.md) (as merged in #83)
- Date: 2026-11-08
- Status: draft

## Overview
Ten tasks in five waves. The spec estimated eight; two were added so that frontend and backend
never wait on each other and so that no two parallel tasks own one file:

- **Wave 1** lays the two contracts nothing else can start without: the core types and traits
  (T1) and the design-system README note (T6, design-first, done by the orchestrator).
- **Wave 2** runs four tasks in parallel on T1: the IPC contract with stub commands and the
  regenerated `bindings.ts` (T2), the timer engine with formatting and the `Hlc` (T3), the new
  `crates/store` (T4) and the macOS platform implementations (T5).
- **Wave 3** builds the session service, the scheduler and the real command bodies in the app
  crate (T7, on T2–T4, against the traits with fakes) while Today and the shell UI (T8) build
  against `bindings.ts` and `mockIPC` (on T2 and T6).
- **Wave 4** wires macOS: the menu-bar item, hide-on-close, Dock reopen, the platform
  selection and the exit flush (T9, on T5 and T7).
- **Wave 5** accepts the ADRs, updates the conventions and the spec status, and carries the
  owner's manual acceptance checklist (T10).

Core is cut in two (T1 types and traits, T3 engine and formatting) so the IPC contract (T2) and
the store (T4) can start after a small, quick task instead of after the whole engine. The app
crate is cut in two (T7 cross-platform service, T9 macOS glue) along the same line as the spike
(S5a/S5b): T7 is testable on every OS with fakes, T9 is the AppKit and tray work.

**Conventions for every task** (from `docs/conventions.md`, `docs/common-issues.md` and the
earlier plans): IPC structs and enums use `#[serde(rename_all = "camelCase")]`, enum variants
are lowercase or camelCase as the spec spells them; every `u64` that crosses IPC carries
`#[specta(type = specta_typescript::Number)]` (an `Option<u64>` carries
`#[specta(type = Option<specta_typescript::Number>)]`), because specta-typescript 0.0.13 exports
`f64` as `number | null`; `bindings.ts` is generated by `cargo test -p orasenda export_bindings`
and never edited by hand; every command goes into `commands.list.rs` **and** a capability file;
no lock is held across an AppKit call; `unsafe` blocks carry a `// SAFETY:` comment; green CI
means `gh pr checks <pr> --required` passes and a red `windows (advisory)` is reported, not
fixed; `Cargo.lock` and `pnpm-lock.yaml` are regenerated after a rebase, never hand-merged.
Each task is one squash-merged PR. Tasks marked **mechanical** have a fixed shape and a
complete contract to type against; tasks marked **cross-file/debugging** need judgement across
modules or the running app.

  builds against `bindings.ts` with `mockIPC`; T7 replaces the stub bodies.

  T4's Produces. T7 consumes them.
- **Platform contract (T5):** `MacKeepAwake`, `MacLocalTime`, `MacNotifier`, `is_app_bundle`.
  T9 consumes them.
- **Service contract (T7):** `SessionService`, `Action`, `Effects`, `NativeSurface`,
  `scheduler::publish`. T9 consumes them.
- **Design-system contract (T6):** the `MenuBarTimer` README "Menu-bar glyphs" note with the
  three shapes T9 draws.

## Impact
Risky changes: a new database and schema, a larger IPC public surface, the shell ticker
replaced, the window lifecycle changed, the CI script extended.
- **Schema (T4):** new file `orasenda.db` under `app_data_dir()`; `0001_init.sql` creates
  `meta`, `change_log`, `setting`, `focus_session`, `active_session`; `PRAGMA user_version = 1`.
  No existing data, so expand → migrate → contract collapses to "create". A newer
  `user_version` is refused and the app runs degraded (`store: newer`); nothing is written.
  Rollback of the feature leaves the file in place and unread, which is harmless.
- **IPC public surface (T2):** `ClockTick` gains `clock: string` and `idleFinish: string | null`
  (additive; the shell's `useClock` keeps working until T8 replaces it); seven new commands,
  two new events. `bindings.ts` is regenerated in T2 and again whenever a type changes; the
  `windows (advisory)` job regenerates it too, so every new type must exist on every OS (none
  is `cfg(target_os)`-gated).
- **Ticker replacement (T7):** `ticker.rs` is deleted and `scheduler.rs` takes over
  `clock-tick`; `lib.rs` calls `scheduler::spawn` and `scheduler::publish_clock` where it called
  `ticker::spawn` and `ticker::emit_now`. The shell's `clock-tick` contract stays (one tick a
  second, one on `Focused(true)`), so `App.test.tsx`'s clock tests keep passing until T8.
- **Close-to-hide (T9):** `CloseRequested` on `main` is prevented and hides; the process stays
  alive with the menu-bar item; ⌘Q and *Quit Orasenda* quit. Rollback: revert T9 and the app
  quits on close again, with no data effect (the live session is persisted on every
  transition).
- **CI script (T1, T4):** `just core-boundary` also rejects `rusqlite` and `libsqlite3-sys`; a
  new `just core-purity` step fails when `grep -rn 'cfg(target_os' crates/core/src` matches
  anything; the mobile step becomes `cargo check -p orasenda-core -p orasenda-store -p orasenda`
  for both targets and **needs an Android NDK clang** for the `bundled` SQLite C build (see
  Dependencies): the recipe exports `CC_aarch64_linux_android` and `AR_aarch64_linux_android`
  from `ANDROID_NDK_HOME` (or `ANDROID_NDK_LATEST_HOME`, which GitHub's macOS images set) and
  fails with a message naming the variable when neither is set. If the `macos-26` runner image
  has no NDK, the workflow installs one with `sdkmanager` in a pinned step. The Windows advisory
  job compiles SQLite with MSVC's `cl`, which `cc` finds on its own.
- **Tests and downstream checks that must stay green:** the core boundary step, core mobile
  check, `bindings.ts` staleness on macOS and Windows, the spike's Vitest suites
  (`DevPanel.test.tsx`, `useSpike.test.tsx`, `overlay.test.tsx`), `manifest_commands_match_specta_builder`,
  `main_capability_includes_spike_commands`, `styles.test.ts` (the token-only CSS rule now also
  covers Today's CSS).
- **Rollout and rollback:** each task is one squash-merged PR; revert that PR to roll back.
  T6's design-system change is rolled back by republishing the previous artifact version and
  refreshing `design/system/`.

## Spec gaps found while planning (not patched here; listed for the owner)
1. **Android `cargo check` of `rusqlite` `bundled` needs an NDK clang.** `cc` 1.11.1 does not read `ANDROID_NDK_HOME`; the spec's CI line and the workflow assume `cargo check` alone. T4 adds the exports to the justfile and, if the runner lacks an NDK, a workflow step.
2. **`id: Uuid` in core vs. "uuid: app crate only"** in the dependency table. The plan carries the id as `SessionId(String)` in core and makes it in the app crate.
3. **The device id is a random UUIDv4** but the store "never reads the clock" and `uuid` is app-crate only. The plan passes `new_device_id` into `Store::open` and adds the `v4` feature to the app crate's `uuid`.
4. **The `Hlc` needs `now_ms` for every stamp**, so ADR-012's `store.write(|txn| …)` becomes `store.write(now_ms, |txn| …)`.
5. **The permission answer while idle:** the spec says the explanation line disappears "as soon as" the status changes but also that nothing is emitted on `timer-tick` while idle. The plan emits one `timer-tick` on the answer in every state.
6. **Default `timer.preset`** is not named; the plan uses `classic` (the TL;DR's checked radio).
7. **Tray icons at 1x and 2x:** `TrayIcon` takes one `Image`; how `tray-icon` 0.25 picks the retina scale is unverified. T9 checks by hand and falls back to one asset.
8. **The spec says "the first UI task updates the artifact"**; the owner asked for a separate design-first task (T6), which this plan does.
9. **`spoken_remaining(0)`** and `TimerView::idle` strings are not specified; the plan uses "0 seconds" and `00:00`.
