- Status: draft

## TL;DR
- Orasenda gets a working app shell built with **Tauri 2, React 19 and TypeScript**. Product logic lives in a **Rust core** (`crates/core`) that never depends on Tauri or OS APIs.
- **macOS 13+ gates all work.** Windows 11 runs the same checks in an advisory CI job. iOS and Android projects are generated and smoke-tested by hand.
- `scripts/ci.sh` gains formatting, lint (including accessibility), typecheck, tests, contract checks and a debug app build. `baton validate` and CI run it.
- The shell renders with the design system's tokens, generated from `design/system/tokens.json` into a shared `packages/tokens` package that the website will reuse.
- The repo becomes a monorepo: pnpm and Cargo workspaces manage packages, and `just` is the single task runner (`just dev`, `just ci`, …).
- Decisions: ADR-001 (stack and code sharing), ADR-007 (typed IPC via a pinned tauri-specta 2 RC).

## Change in a nutshell
`pnpm --filter orasenda tauri dev` opens a calm 900×600 window on the design system's `surface`:

```
Orasenda 0.1.0 · macOS aarch64
14:32                    ← wall clock, mono tabular digits, driven by a Rust event
```

The version and platform come from the Rust core through a typed command. The clock is updated by a Rust event every whole second and stays correct while the window is hidden. This proves the rule every later phase relies on: **logic and time live in Rust; React renders.**

## Problem
The stack is the first P0 decision and every later phase builds on it. Two properties must exist from the first commit, because retrofitting them is expensive: timing must not depend on a webview that the OS throttles when hidden, and the core must stay free of any one platform so Windows, mobile and a later web build can reuse it.

## Goals / Success criteria
1. On macOS, `pnpm --filter orasenda tauri dev` and `pnpm --filter orasenda tauri build` work; the built `.app` launches and shows the version line and a wall clock.
2. The clock stays correct while the window is hidden: after ⌘H or minimize for 2+ minutes, the shown minute matches the system clock within 1 s of showing the window.
3. `crates/core` has no `tauri`, `tao` or `wry` in its dependency tree, enforced by `scripts/ci.sh`.
4. `crates/core` builds for `aarch64-apple-ios` and `aarch64-linux-android`, enforced by `scripts/ci.sh`.
5. `apps/orasenda/src/bindings.ts` is generated from Rust and committed; `scripts/ci.sh` fails when it is stale.
6. `./scripts/ci.sh` passes locally on macOS and in the required CI job `ci` (macOS). The `windows (advisory)` job runs the same script and does not block merging.
7. The iOS and Android projects are generated and committed, and README documents how to run them. Running them is a manual, non-blocking smoke check.
8. The UI uses only design-system tokens (no hard-coded colors, sizes or font names; layout keywords such as `display: flex` and the unitless `0` are not design values and are allowed) and passes Biome's accessibility rules as errors.
9. ADR-001 and ADR-007 are accepted in `docs/DECISIONS.md`; SPEC, ROADMAP and CLAUDE.md reflect the platform tiers (done with this spec). README lists the prerequisites (rustup, Node 24, pnpm, just, gitleaks, Xcode, Android SDK/NDK) and run commands (done by the implementation).

## Non-goals
- P1 features: focus timer, menu-bar item, floating timer, hide-on-close, storage.
- OS integrations: foreground-app detection, overlays, App Nap activity assertions. The spike (next P0 spec) decides where platform code lives.
- Packaging for distribution: `.dmg`, signing, notarization, updater (ADR-003).
- Mobile CI, Linux CI, a manual Windows run, automated end-to-end tests.
- Bundled font files. The shell uses the token font stacks, which fall back to system fonts until the OFL fonts are added (design system README, "Fonts ship inside the app bundle").
- Any UI beyond the version line and the wall clock.
- `apps/website`, `apps/web` and `packages/ui`: the layout reserves them (see ROADMAP) but this spec creates only `apps/orasenda`, `crates/core` and `packages/tokens`.

## Users & permissions
One local user, no accounts. "Permissions" here are what the webview may do; least privilege applies.

| Caller | Can | Cannot |
|---|---|---|
| Webview in window `main` | call `app_info`; listen to and unlisten from events | any other Tauri API (fs, shell, http, …); load remote content |
| Any other window or origin | nothing | everything |

- `build.rs` declares app commands with `tauri_build::AppManifest::commands(&["app_info"])`. Without it, app commands are allowed for every window by default.
- `src-tauri/capabilities/main.json` grants window `main` exactly: `core:event:allow-listen`, `core:event:allow-unlisten`, `allow-app-info`. Rust→JS emits need no permission.
- No Tauri plugins are installed.
- CSP (production): `default-src 'self'; connect-src 'self' ipc: http://ipc.localhost; img-src 'self' data:; style-src 'self'`. `devCsp` additionally allows `http://localhost:1420`, `ws://localhost:1420` and inline styles injected by Vite in dev. No network access in either.

## Tenancy & localization
- Single user, single device; no tenancy.
- UI copy is English only; no i18n framework yet.
- Rust sends UTC epoch milliseconds. The UI formats them with `Intl.DateTimeFormat` using the system locale and time zone, `hour: "2-digit", minute: "2-digit"` (no seconds: the design system reserves seconds for countdowns). The formatter is created on each render, so a time-zone change shows on the next tick when WebKit picks it up.
- WKWebView's `Intl` follows the language-derived locale and may ignore the macOS Region format and 24-hour override. This is best effort in the shell, checked by manual steps 6–7; if it fails, P1 passes locale and hour cycle from Rust.

## Domain model
No stored data. Types, all in `crates/core` unless noted:

- `Os` — `macos | windows | linux | ios | android | other`; `Os::from_consts(&str) -> Os` never panics (unknown → `other`). Serialized lowercase.
- `AppInfo { name: String, version: String, os: Os, arch: String }` — `AppInfo::new(name, version)` fills `os` and `arch` from `std::env::consts`. Name and version come from the caller (the app's `package_info()`), never from core's own `CARGO_PKG_*`.
- `clock::delay_to_next_second(now: SystemTime) -> Duration` — pure; returns a value in (0, 1 s]: `1 s − subsec`, exactly 1 s on a boundary. Pre-epoch input does not panic.
- `clock::epoch_ms(t: SystemTime) -> u64` — pure.
- `ClockTick { epoch_ms: u64 }` — **in the app crate**, because the event derive needs tauri-specta. Serialized camelCase (`epochMs`); exported to TypeScript as `number` via `#[specta(type = specta_typescript::Number)]` (lossless: epoch ms ≪ 2^53). Event name `clock-tick`.

Core never calls `SystemTime::now()`; the app crate passes time in. This keeps core testable and open to a later WebAssembly build.

**Command** `app_info() -> AppInfo` — infallible in Rust; builds `AppInfo::new` from `app.package_info()`.

**Event** `clock-tick` with `ClockTick`. A thread named `clock-ticker`, started once in `setup()` after the specta builder mounts events, loops forever: sleep `delay_to_next_second(SystemTime::now())`, then emit `ClockTick` read from `SystemTime::now()` after waking. Additionally, on `WindowEvent::Focused(true)` the app emits one tick immediately, so the display is correct as soon as the window is shown even if App Nap delayed the thread.

**Bindings** — one `specta_builder()` function in the app crate is used by `run()` (which also exports bindings under `#[cfg(all(debug_assertions, desktop))]`, so mobile debug builds never write a host path) and by the test `export_bindings`, which writes `apps/orasenda/src/bindings.ts`.

**Tokens** — `just tokens` (`pnpm --filter @orasenda/tokens build`) reads `design/system/tokens.json` and writes `packages/tokens/tokens.css`: `:root` custom properties for every token, light color values by default, dark values under `@media (prefers-color-scheme: dark)`, type styles as `--type-<name>-*`. The file is committed; `ci.sh` fails when it is stale. `bundle.css` is not imported (it carries a preview-only font CDN import).

**UI** — `App.tsx` renders one `<main>`: a header row with an `<h1>` "Orasenda" in the `heading` style and, beside it, a `<p>` with the info line ("0.1.0 · macOS aarch64") in `body-sm` `ink-muted`, joined visually by " · "; below it the wall clock as a `<time>` in `--font-mono`, `timer-md`, tabular digits. `useClock()` subscribes on mount and unsubscribes on unmount. The clock has no `aria-live`.

## Behavior & edge cases
- **Window:** Tauri defaults. Closing the `main` window or ⌘Q quits the app. ⌘H and minimize keep the process and the ticker running. No hide-on-close and no Dock reopen (P1).
- **Before the first tick:** the `<time>` element reserves its width and is empty; the first tick arrives within 1 s.
- **After a tick:** shows the formatted minute; `dateTime` holds the full ISO timestamp (with seconds).
- **Emit failure:** logged with `eprintln!`; the loop continues.
- **System sleep, clock jumps, NTP corrections:** each iteration re-reads the wall clock, so the next tick is realigned; the focus tick covers the moment the window returns.
- **Time-zone change:** the next tick formats in the new zone if WebKit reports it; otherwise it is a known issue for P1 (manual step 6 records which).
- **React StrictMode double mount:** `useEffect` stores the `listen` promise; cleanup sets `cancelled = true` and calls the unlisten function when the promise resolves. The handler ignores events after cancellation. Exactly one live listener remains.
- **`app_info` failure** (only possible through IPC, e.g. a missing permission): the `<p>` reads "version unavailable" in `ink-muted` (the `<h1>` is unchanged); the error goes to `console.error`. No alert styling.
- **`clock-tick` listen failure** (only possible through IPC, e.g. the `core:event:allow-listen` permission missing from the capability): the clock slot renders a `<p>` reading "clock unavailable" in `body-sm` `ink-muted`, occupying the same box as the `<time>` so nothing shifts; the `<time>` is not rendered because it would hold no time. The error goes to `console.error`. No alert styling, no `aria-live`. The state is final: no tick can arrive after a failed subscription.
- **OS labels:** `macos` → "macOS", `windows` → "Windows", `linux` → "Linux", `ios` → "iOS", `android` → "Android", `other` → the raw value. `arch` is shown as reported (`aarch64`, `x86_64`).

## Testing strategy
**Rust — `crates/core`** (`cargo test`)
- `delay_to_next_second`: exact boundary → 1 s; mid-second; 999 ms → 1 ms; `UNIX_EPOCH`; pre-epoch input; result always in (0, 1 s].
- `epoch_ms` for a known instant.
- `Os::from_consts` for the five known values and an unknown one → `other`.
- `AppInfo::new` keeps the given name and version and fills `os`/`arch` from `std::env::consts`.

**Rust — app crate**
- `export_bindings` regenerates `bindings.ts` (the staleness check compares it with the committed file).
- A test asserts the `AppManifest` command list equals the command names registered in `specta_builder()`.

**UI — Vitest 5 + jsdom + Testing Library**, using `mockIPC(handler, { shouldMockEvents: true })` and `clearMocks()` in `afterEach`:
1. Renders the heading "Orasenda" (by role) and the info text "0.1.0 · macOS aarch64" from a mocked `app_info`.
2. A rejected `app_info` renders "version unavailable" and keeps the heading.
3. The clock is empty before the first tick.
4. After `emit("clock-tick", { epochMs })` the clock shows the expected text (formatter called with `"en-US"` and `"UTC"` in tests so results don't depend on the host).
5. Under StrictMode one emit causes exactly one update, and an emit after unmount neither throws nor updates.
6. A rejected clock-tick listen renders "clock unavailable", renders no `<time>`, and keeps the heading.

**Contract checks in `ci.sh`** — bindings and tokens staleness, core dependency boundary, core mobile `cargo check` (below).

**End-to-end:** none automated. tauri-driver has no macOS support (WKWebView has no WebDriver).

**Manual macOS acceptance** (recorded in the PR):
1. Fresh clone: `pnpm install --frozen-lockfile`, then `./scripts/ci.sh` passes.
2. `pnpm --filter orasenda tauri dev` shows "Orasenda 0.1.0 · macOS aarch64" and the current minute; the minute changes within 1 s of the menu-bar clock.
3. ⌘H for 2+ minutes, show from the Dock: correct minute within 1 s.
4. Minimize for 2+ minutes, restore: correct minute within 1 s.
5. `pmset sleepnow`, wake: correct minute within 1 s.
6. Change the time zone in System Settings: record whether the clock follows.
7. Toggle the 24-hour setting: record whether it is honored.
8. Close the window: the process exits.
9. `pnpm --filter orasenda tauri build` produces a `.app`; launch it, repeat steps 2–3, and record the "App Nap" column in Activity Monitor while hidden.
10. Light and dark appearance both render from tokens; VoiceOver reads the heading, the version line and the time.

**Manual mobile smoke** (non-blocking): `pnpm --filter orasenda tauri ios dev` in the Simulator shows "iOS aarch64" and a ticking clock; `pnpm --filter orasenda tauri android dev` in the emulator shows the Android line and a ticking clock.

### `just ci`, in order
`scripts/ci.sh` is `exec just ci`; the recipe runs these steps in order and stops at the first failure (bash with `set -euo pipefail`).
1. Secrets: `gitleaks git --no-banner --redact --log-opts="${base}..HEAD"` (existing).
2. `pnpm install --frozen-lockfile --prefer-offline`.
3. `cargo fmt --all --check`.
4. `pnpm exec biome ci .` — formatting, lint with the whole `a11y` group as errors, import order. Ignores `apps/orasenda/src/bindings.ts`, `packages/tokens/tokens.css`, `**/src-tauri/gen/**`, `dist`, `target`.
5. Core boundary: `cargo tree -p orasenda-core --locked --target all -e normal,build,dev --prefix none --format '{p}'` must contain no line starting with `tauri`, `tao` or `wry`.
6. Tokens: `pnpm --filter @orasenda/tokens build`, then `git diff --exit-code -- packages/tokens/tokens.css`.
7. `pnpm --filter orasenda typecheck` (`tsc --noEmit`).
8. `pnpm --filter orasenda test` (`vitest run`).
9. `cargo clippy --workspace --all-targets --locked -- -D warnings`.
10. `cargo test --workspace --locked` (regenerates bindings).
11. Bindings: `git ls-files --error-unmatch apps/orasenda/src/bindings.ts` and `git diff --exit-code -- apps/orasenda/src/bindings.ts`.
12. Core mobile: `cargo check -p orasenda-core --locked --target aarch64-apple-ios --target aarch64-linux-android`.
13. `pnpm --filter orasenda tauri build --debug --no-bundle --ci` — exercises embedded assets, CSP and capabilities, which `dev` skips.

No `pnpm audit` or `cargo deny` in `ci.sh`: they need the network; the `baton:deps` vet covers new dependencies.

### CI workflow (`.github/workflows/ci.yml`)
- Branch protection requires the context `ci` (strict), so the macOS job keeps id and name `ci` and has no matrix.
- `concurrency: { group: ci-${{ github.ref }}, cancel-in-progress: true }`.
- **Job `ci`** — `runs-on: macos-26`, `timeout-minutes: 45`: checkout (`fetch-depth: 0`), `pnpm/action-setup` (reads `packageManager`), `actions/setup-node` (`node-version-file: .node-version`, `cache: pnpm`), `rustup toolchain install` (reads `rust-toolchain.toml`), `Swatinem/rust-cache`, just 1.59.0 via `gh release download` with SHA256SUMS verification and retries (#51), gitleaks `darwin_arm64` with checksum verification, `./scripts/ci.sh`.
- **Job `windows`** (name `windows (advisory)`) — `runs-on: windows-2025`, `defaults.run.shell: bash`, the same steps with gitleaks `windows_x64.zip`. Not a required check and no `continue-on-error`: a red result is the advisory signal.
- Actions pinned by commit SHA with a version comment: `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1`, `pnpm/action-setup@73e46992e05b19abd31f2f3c20e0e7370d762115 # v6.1.1`, `actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7.1.0`, `Swatinem/rust-cache@d1527c8f67ef9af357290475d4af4b0fab8f12e0 # v2.9.3`.

## FAQ
### Why Tauri rather than Electron, Flutter, React Native or native Swift?
See ADR-001. In short: the hardest features are native (foreground-app detection, overlays, anti-quit helper), Rust reaches those APIs directly on every OS, the same core runs on iOS and Android, and the app stays small for something that lives in the menu bar.

### Why a Rust core instead of TypeScript logic?
Timers, blocking and tracking must keep running while the window is hidden. WebKit throttles timers in hidden pages and macOS App Nap throttles hidden apps; logic in a Rust thread is unaffected by the first and can be protected from the second with an activity assertion (P1).

### Why Biome rather than ESLint?
Forced by peers: typescript-eslint 8.72.1 supports TypeScript < 6.1 and eslint-plugin-jsx-a11y 6.10.2 supports ESLint ≤ 9. Biome lints, formats and sorts imports in one binary and has a complete a11y rule group.

### Why does closing the window quit the app?
It's Tauri's default and the shell has no menu-bar item yet. P1 adds the menu-bar timer and switches to hide-on-close.

### Why a debug Tauri build in `ci.sh`?
`tauri dev` serves assets from Vite and skips the custom protocol, embedded assets, production CSP and capability checks. The debug no-bundle build covers them without signing or packaging.

### Why no seconds on the clock?
The design system reserves seconds for countdowns ("Seconds appear only in countdowns"). The acceptance check watches the minute change instead, and `dateTime` carries the exact time.

### Why `just` rather than Make, cargo xtask, pnpm scripts or Turborepo?
The repo mixes Rust and TypeScript. `just` runs both, behaves the same on macOS, Windows and Linux, and takes arguments. Make is awkward on Windows; `cargo xtask` is heavy for plain commands; pnpm scripts hide Rust steps; Turborepo, Nx or moon pay off only with many slow packages. Revisit moon if the repo grows.
