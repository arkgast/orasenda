## TL;DR
- A **Board** page joins the rail after Inbox. Pages become Today, Inbox, Board, Calendar, Routines, Review, Settings on ⌘1–⌘7.
- **Tasks** live in a new syncable `task` table (migration 0008) behind a store repository, a `board` service module and IPC with a `board-changed` event.
- **Four columns: Backlog → Today → Doing → Done.** The user can rename them and set the Today and Doing limits. Limits inform, never block, and never use red.
- **Fields:** title, notes, tags, Deep or Shallow, estimate in sessions, tracked time, due date, priority, checklist. A **buffer** (25% by default, 25–50%) pads planning; **Break it down?** appears past 4 sessions; **one Frog a day**.
- **Inbox → Board:** an Inbox note gets **Move to Board**, which makes a Backlog task and removes the note, with Undo. There is no Inbox column.
- **A session can pick a task** (#465), always optional: Start links the task the user chose, if any, the timer shows its title, and the task's tracked time grows by each focus session. Done cards read *estimated vs actual*. A session with no task is normal and nothing asks for one.
- **Keyboard-complete:** every action on the Board works from the keyboard.

## Problem
P1 made Orasenda a good focus timer, but a session is about nothing: H2 removed the free-text intent and promised a Board task instead (#465). Captured notes pile up in the Inbox with nowhere to go. P2's exit criterion, "every session is linked to a task, with estimated vs actual time", can't be met without tasks.

## Goals / Success criteria
1. A person can add, edit, move, reorder, flag and remove tasks on a four-column Board, by keyboard alone and with VoiceOver names on every control.
2. Limits read in words and shape: "At limit", "4 of 3", never red, never blocking.
3. Starting a session with a task selected links it. The task's tracked time and session count grow when each focus session ends, and the card reads estimated vs actual.
4. An Inbox note becomes a Backlog task in one action, with Undo.
5. One Frog a day, a buffer on estimates, a breakdown prompt past 4 sessions.
6. Tasks survive export, import (merge and replace) and backups like every other table.
7. Every new or changed component has a README, tests and specimens in both themes, and the design-system artifact is republished from main.

## Non-goals
- Task import from Apple Reminders, Todoist or Things (follow-up issue, still P2).
- Calendar blocks and time blocking (P3). Projects as an entity (tags only for now).
- Adding, removing or reordering columns; pointer drag-and-drop (follow-up issue; keyboard and the Move menu move cards).
- Auto-tuning the buffer from history (follow-up issue; needs weeks of data).
- Recurring tasks, subtasks as tasks, reminders or notifications for due dates.
- Linking a routine step to a task (the Routines spec's non-goal too).

## Users & permissions
One local user. No system permission is needed.

## Tenancy & localization
Copy in English, plain and kind (CLAUDE.md UI rules). Dates and times use the user's local time zone through the service, as the Inbox does ("Due Fri 20 Nov", "Due today", "Due yesterday": never "overdue" and never red).

## Domain model

### Columns
`backlog`, `today`, `doing`, `done`: a fixed set with fixed meaning. The user edits each column's **name** (1–24 characters) and the **limits** of Today (default 3, 1–9) and Doing (default 1, 1–3). Names and limits are one setting row, `board.columns` (JSON), synced like other settings but read and written only through the board service (`board_columns_set`), not the `Settings` struct.

### Task (`task` table, syncable)
| Field | Type | Rules |
|---|---|---|
| `id` | TEXT UUIDv7 | |
| `title` | TEXT | trimmed, 1–200 characters |
| `notes` | TEXT | 0–10 000 characters |
| `tags` | TEXT (JSON array) | at most 8, each 1–24 characters, trimmed, case-insensitively unique, kept in the order typed |
| `kind` | TEXT | `deep` or `shallow`, default `deep` |
| `estimate` | INTEGER NULL | sessions, 1–16; NULL means "No estimate" |
| `due` | TEXT NULL | local date `YYYY-MM-DD` |
| `priority` | TEXT NULL | `high`, `medium`, `low`; NULL means none |
| `checklist` | TEXT (JSON array) | at most 30 items `{id, text (1–200), done}` |
| `lane` | TEXT | `backlog`, `today`, `doing`, `done` (named `lane`, not `column`, beside `ADD COLUMN` SQL) |
| `rank` | TEXT | fractional index within the lane (sortable string), so a move writes one row; equal ranks (two devices) sort by `id` |
| `frog_day` | TEXT NULL | the local date the task is that day's Frog; if a merge leaves two for one day, the newest `updated_at` is the Frog |
| `breakdown_dismissed` | INTEGER 0/1 | "Keep as is" was chosen on the breakdown prompt |
| `source_note_id` | TEXT NULL | the Inbox note it came from |
| `done_at`, `created_at`, `updated_at` | INTEGER ms | `done_at` NULL unless in Done |
| `deleted_at` | INTEGER NULL | tombstone, so Undo can restore |

Every write logs `change_log` rows with `entity = 'task'`, one per changed field, like `inbox_note`.

### Tracked time
**Derived, never stored.** `focus_session` gains a nullable `task_id`. A task's tracked time is the sum of `focused_ms` and its session count is the number of focus rows (not breaks) with its id and no tombstone. No counter can drift or double-count across devices.

### Buffer
A setting `board.estimate_buffer`, a field of the `Settings` struct (snake_case like `timer.auto_continue`), a whole percent in {25, 30, 35, 40, 45, 50}, default 25. A task's **planned** sessions are, in integers, `ceil(estimate × (100 + buffer) / 100)`. The Today footer sums the planned sessions of its tasks that have an estimate. The raw estimate is stored and shown on the card; the buffer appears where planning happens: the Today column's footer ("Planned 9 sessions with a 25% buffer") and the task detail ("Estimate 3 · 4 with buffer").

### Frog
At most one task has `frog_day` equal to today. Setting a Frog clears any other task's `frog_day` for that day in the same transaction (a toast says "Frog moved to <title>", with Undo, which restores the previous Frog). The Frog reads as the word "Frog" in `TaskCard`'s label slot, never colour alone and never an emoji. On Today it appears through the task slot (the default pick, marked "Frog" in its menu). A Frog from an earlier day is no Frog today and shows nothing. A Done task can't be made the Frog.

## Interfaces

### Store (`crates/store`)
- `migrations/0008_board.sql`: the `task` table with CHECKs, an index on `(deleted_at, column, rank)`, and `ALTER TABLE focus_session ADD COLUMN task_id TEXT NULL` with an index on it. `SCHEMA_VERSION` 8.
- `repo/tasks.rs` (+ `tasks/tests.rs`): `insert`, `update` (field-wise, logging only changed fields), `move_to` (lane + rank, sets or clears `done_at`), `set_frog`, `remove`, `restore`, `list_live`, `get`, and `tracked` (per-task sums from `focus_session`). No rusqlite type crosses the boundary.
- `focus_sessions::insert` writes `task_id` from the record and logs it to `change_log`.
- Portability: `rows.rs`, `snapshot.rs`, `merge` and `stats.rs` cover `task` and `focus_session.task_id`; merge is newest-`updated_at`-wins like the other syncable tables, and `merge/sessions.rs` adds `task_id` to its column list. Known limit: inbox merge lets a tombstone win, so an Undo of *Move to Board* on one device can be lost on import into another (accepted; the task stays).

### Core (`crates/core`)
- `SessionRecord`, the engine's live session and its `open_focus` gain `task_id: Option<String>` with `#[serde(default)]` (a v7 snapshot still loads). Focus records carry it; break records don't. A focus row is written when the whole session ends, after its break, so tracked time grows then.
- A pure `rank` helper (between, before, after) for fractional indexes, with tests.

### Service (`crates/service`)
- `board/` module, `run_*` functions like `inbox/`: `board_get`, `task_add`, `task_update`, `task_move`, `task_reorder`, `task_set_frog`, `task_remove`, `task_restore`, `inbox_to_task`, `task_restore_note`, `board_columns_set`, `timer_set_task`. Each writes under the service lock and emits `board-changed` with the whole `BoardView` and a sequence number after the lock (newest `seq` wins, `conventions.md`). The board is re-emitted at the day roll, so due words, the Frog and the Done window never go stale.
- `BoardView`: the columns in order with name, limit, count, limit state (`under`, `at`, `over`) and `TaskView`s; the buffer; today's date.
- `TaskView`: every field, worded dates (`dueLabel`), `tracked` ("0h 41m"), `sessions` (count), `planned` (with buffer), `isFrog`, `active` (a session is running on it).
- Done shows tasks done in the last 14 days, newest first; older Done tasks stay stored and in exports, off the board.
- **The chosen task (optional).** The service holds the task the user chose for the next start, or none. **Nothing is chosen automatically**: no default from Doing or the Frog (owner ruling). `timer_set_task(taskId | null)` while idle sets or clears the choice; while a focus runs it changes the live session's task; during a break it changes `open_focus`'s task (its row isn't written yet). The choice stays until the user clears or changes it, or the task is removed or moved to Done. **Every start path** (Today, Space, the tray, the floater, the menu, the global key, roll-on) links the chosen task if there is one, and starts with no task otherwise. Roll-on and Keep going keep the previous session's task. The whole session counts to the task linked when its row is written.
- `StartRequest` gains `taskId: Option<String>` with `#[serde(default)]` (optional in TS); when present it overrides the next task. A task id that isn't live is refused with `TaskNotFound` ("That task is gone. Pick another or start without one."); a Done task is refused ("Move it out of Done first.").
- **Starting a session on a task moves it to Doing.** Only if Doing would then go over its limit, the task longest in Doing moves back to the top of Today, said in a toast ("Moved <title> back to Today."). If that store write fails, the session still starts and a toast says "The board didn't update. Try again."
- **When a session ends** the task stays where it is (usually Doing). Nothing prompts; the user moves it to Done when it is done.
- `TimerView` gains `task: Option<{id, title}>`, read from a cache the service refreshes on `task_update` and `task_remove`, never from the store per tick.
- `inbox_to_task(noteId)`: one transaction makes a Backlog task (title = the note's text up to 200 characters on a word boundary, the rest in notes; `source_note_id` set) and tombstones the note. Emits `inbox-changed` and `board-changed`. Its Undo (`task_restore_note`) tombstones the task and restores the note.

### Board page (`features/board/`)
- **One primary action:** *Add task* (⌘N while the Board is shown). It focuses the Backlog's *New task* field; Enter adds and keeps the field ready for the next; Esc leaves it.
- **Keyboard:** the board is one roving-focus grid.
  - ←/→ move between columns, ↑/↓ between cards; Home/End to first and last card.
  - Return opens the task detail (Space too, as on any native button); Esc closes it and returns focus to the card.
  - ⌥⌘← / ⌥⌘→ move the selected card one column; ⌥⌘↑ / ⌥⌘↓ reorder it. The same moves are in the card's **Move to** menu (⌘⏎ on macOS is Start focus, so no Return chords).
  - ⌘⏎ (Start focus) with a card selected starts a session on it.
  - ⌘⌫ removes with an Undo toast; F toggles the Frog (single key, honouring "Use single keys").
  - **These are page keys, not registry keys.** The Board handles them in its own `onKeyDown` (the shared `useSingleKeys` fires only at rest and `useShortcuts` drops ⌥ keys), so F works on a focused card. They are not added to the registry's `FIXED` list, so they never override a user's binding; a user binding on ⌘N wins over Add task, which stays one click away. Settings › Shortcuts shows them as a read-only *On the Board* list, and the single-keys label reads "Use single keys (Space, P, F, B)".
- **Limits:** the column count reads "2 of 3" under the limit and "At limit" at it, both as plain captions, and "4 of 3" over it in the `warning` chip (amber with a shape, never red). See Decision 19. Moving past a limit is allowed.
- **Empty board:** `EmptyState` "No tasks yet. Add one, or move a note from the Inbox." with *Add task*.
- **Failure line:** if the board can't be read, an `InlineNotice` "The board couldn't be loaded. Try again." with *Try again*, never an empty board.

### Task detail
A sheet over the board (owner pick 2B: `Dialog` at `sheet-width` over the scrim, a two-column field grid that stacks when narrow) with: title (Input), Deep/Shallow (Choice), estimate (Stepper, "No estimate" at 0), due (date Input), priority (Select), tags (TagField), checklist (Checklist), notes (TextArea), column (Select), Frog toggle, and the record: "Estimate 3 · 4 with buffer · Actual 4 sessions, 1h 40m". Edits save on change (debounced like Settings), never with a Save button.
- **Breakdown prompt:** when the estimate is above 4 and `breakdown_dismissed` is false, an `InlineNotice` reads "This looks big. Could it be a few smaller tasks?" with *Add a checklist* (focuses the checklist) and *Keep as is* (sets `breakdown_dismissed`).

### Inbox page
`InboxRow` changes: the row becomes focusable (roving, ↑/↓) with a row menu holding **Move to Board** and Remove; B on a focused row moves it (single-key setting honoured, in the row's own `onKeyDown`). A toast "Moved to Board" offers Undo and *Open Board*.

### Session ↔ task
- **Today page:** a `TaskPicker` above the ring, **subtle** (owner ruling): with no task it is a quiet `ink-muted` text button "Add a task" (no border, no fill, hit-min, focus ring), never competing with Start. Activating it turns it into an input (ARIA combobox): typing filters the live tasks that aren't Done (Doing first, then Today, then Backlog, each option naming its column in words, the Frog marked "Frog"), and the options appear while typing (and on ↓). Enter picks, Esc cancels and restores the quiet text. With a task chosen it reads the title as quiet text with a small "Clear task" icon button. While a session runs the same control changes or clears the session's task. Nothing on Today asks for a task.
- **Timer surfaces:** `TimerRing`, `TimerStrip`, `FullScreenFocus` and `FloatingTimer` regain a `task` prop (one line, ellipsis, full title in the accessible name). Each gets its own design review (as #465 asks).
- **Card:** the running task's card is `active` ("In progress") and its tracked time updates when each focus session ends.
- **Settings › Timer:** a row *Estimate buffer* (Select 25–50%) with the line "Padding for the planning fallacy. Your estimates stay as you wrote them."

## Behavior & edge cases
- **Removing a running session's task** clears the session's link (the session keeps running, the slot reads "No task"); Undo restores the task but not the link.
- **Moving the running task out of Doing** keeps the link: the link is to the task, not the column.
- **A task moved to Done** gets `done_at`; moved out, it loses it. Frog flags stay on Done tasks for the record but can't be newly set there.
- **Import (merge)** of a task whose `source_note_id` points to a missing note keeps the task. A `focus_session.task_id` pointing to a missing task counts nowhere and is kept.
- **Two windows** (main and floater) see the same `board-changed` and `TimerView`; the newest `seq` wins.
- **Done count** on the folded strip is the number of tasks the Done column shows (the last 14 days).
- **Store failure** on any write: a toast "That didn't save. Try again." and the board shows the last good view, never a silent success.

## Decisions
Controller rulings (opus), 2026-11-14, under the owner's autonomy ruling:
1. **Fixed four columns with editable names and limits.** Each column's meaning drives behaviour (Doing = being worked, Done = finished), so adding or removing columns would break it. Renaming and limits keep the user in control (principle 2). Column add/remove is a follow-up.
2. **No Inbox column.** The Inbox page is the capture list (#510); a column would duplicate it. *Move to Board* lands in Backlog. SPEC §2.2 is amended.
3. **Limits inform, never block** (Personal Kanban's intent, `KanbanColumn` README, principle 2). Starting a session is the one place Doing is kept at its limit, by moving the other task back to Today, because starting is the user's choice of what they work on now.
4. **Tracked time is derived from `focus_session.task_id`**, not a stored counter: no drift, no double count on sync, and estimated-vs-actual comes straight from the record.
5. **The session's task is the one linked at its end.** Changing task mid-session moves the whole session; splitting time is more bookkeeping than the user needs.
6. **Tags, not projects.** SPEC says "project or tags"; tags cover it without a second entity. Projects can come with P3's planning.
7. **Buffer 25% default, applied to planning, never to the stored estimate.** The user's own number stays theirs; the padding shows where it matters (the day's load). Auto-tuning is a follow-up.
8. **Breakdown prompt is a notice with two kind choices**, not a dialog, and remembers "Keep as is" per task.
9. **One Frog a day, moved not refused.** Setting a second moves the flag with Undo; refusing would add friction for no reason.
10. **Keyboard moves and a Move menu, no pointer drag in P2.** WebKit drag-and-drop in Tauri conflicts with the window's file-drop handling; the `KanbanColumn` README already says the card editor provides the move. Drag is a follow-up.
11. **Done shows the last 14 days.** A calm board; nothing is deleted.
12. **Board keys are page keys** (⌘N, ⌥⌘arrows, ⌘⌫, F; B on the Inbox), handled by the page and not added to the registry's FIXED list, so they never repair away a user's binding. F and B honour "Use single keys".
13. **Migration 0008**, since Routines landed 0007 first.
14. **Linking a task is optional and never automatic** (owner, 2026-11-14: "picking a task MUST be optional"). The service owns the user's choice so every start path honours it (spec review, blocking), but it never defaults one from Doing or the Frog. P2's exit criterion reads "every session can be linked to a task".
15. **Start moves a Doing task back only past the Doing limit**, longest in Doing first.
16. **Ending a session moves nothing**: calm, and the user decides when a task is done.
17. **The task's column is called `lane` in SQL**; the UI still says column.
18. **Design pick, owner (2026-11-14), on the canvas https://claude.ai/artifact/KKtM8f2nNBwU3oneTEkwLJ: board 1B "Today first", task detail 2B "sheet".** The controller had leaned 1A and 2A; the owner chose 1B and 2B. So: Backlog is a narrower list column on the left with `TaskCard` `density="row"`; Today and Doing are the wide centre (a `wide` `KanbanColumn` variant with a new `column-wide-width` token); Done is the folded strip. Below the window width where three open columns fit, Doing folds first, then Backlog, as the README's fold rules say; the board never scrolls sideways. The task detail is a sheet: the `Dialog` at a new `sheet-width` token over the `scrim`, two-column field grid, collapsing to one column when narrow; Esc closes it and returns focus to the card. The design-system README's scrim rule gains the task sheet.
18a. **The task picker is a type-to-filter input behind a quiet control** (owner): a combobox (`TaskPicker`), not a menu button, so a long Backlog stays easy to search; on Today it rests as muted text to keep the screen calm.
19. **"At limit" is neutral, "over" is amber.** At the limit the count reads "At limit" as a plain caption; only over the limit does the `warning` chip appear ("2 of 1"). Doing with its limit of 1 is the normal working state and must not read amber all day (canvas finding). `KanbanColumn`'s README changes with it.
20. **Component gaps from the canvas go to the component tasks:** `KanbanColumn` builds `collapsed`/`onToggle`, a footer and the fold rules its README already promises; `TaskCard` builds `onSelect`/`selected`, due, priority, tags and checklist progress; `Select` is finished and exported; `InlineNotice` takes a second action; `PopoverMenu` takes group headings; `FloatingTimer` shows the task line; tag chips keep hit-min remove targets.

21. **"Longest in Doing" is the first Doing task in rank order** (B9 review, #539). There is no lane-entry timestamp.
22. **`timer_set_task` during a running session only relinks.** It does not move the task to Doing; a start is the only move, which keeps a light action light (#539).
23. **TaskPicker options appear only after typing or ↓**, not when the input opens (owner: an input that shows the options while typing) (#535).
24. **The task sheet opens on the title, its actions row (Close, Done) is pinned and only the fields scroll; the save line takes no space when empty** (its live region stays mounted). `container-sheet-stack` is 600px, so the sheet is one column at 640x480 (#542).
25. **The empty Board keeps the `EmptyState` alignment** shared with Inbox (component contract) (#540).
26. **On Today the TaskPicker is the task's display;** the ring and strip do not repeat the title under the digits. Full screen and the floater keep their task line or name (#543).
27. **No picker in the stacked strip or ring windows under 480 high.** Palette commands to choose or clear a task are a follow-up (#581).
28. **The Board's status line uses the `PageFrame` status row.** (B10 review, #540)
